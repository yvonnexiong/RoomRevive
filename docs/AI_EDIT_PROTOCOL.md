# AI Edit Protocol

**Audience:** any AI agent (Claude, Cursor, Copilot Workspace, etc.) or human collaborator working on RoomRevive.

**Goal:** never silently overwrite manual work. Read the current state first. Touch the minimum needed.

---

## The rule

Before editing any code, prefab, or asset, **read the current authored state and treat it as the source of truth**. Your changes must compose with what's already there, not replace it.

Concretely, follow this order on every task:

1. **Read the snapshot.** For Unity prefabs in the IntentSelector subsystem, that means `Assets/RoomRevive/UI/IntentSelector/Snapshots/*.md`. For other systems, read the prefab YAML or the relevant ScriptableObject `.asset` file directly.
2. **Read the relevant CLAUDE.md / *_AI_Context.md.** These document invariants ("the icon slot is named `IconContent`", "states are ordered by catalog index").
3. **Diff your goal against the current state.** What's already correct? What's missing? What conflicts?
4. **Edit the minimum.** Add missing pieces, fix mistaken ones, leave everything else alone.
5. **If your change destroys user work, stop and ask.** Don't auto-resolve by overwriting.

---

## Three modes, in order of preference

When a script can regenerate something, expose three modes:

| Mode | What it does | When to use |
|---|---|---|
| **Snapshot** | Reads current state, writes a human/LLM-readable report. **No mutations.** | Always run first when you're about to make a non-trivial change. |
| **Sync** | Adds missing components / children / references. Touches nothing that already exists. | Default mode for "make sure this prefab is wired correctly". Safe to re-run constantly. |
| **Rebuild** | Tears down and regenerates from scratch. **Destroys overrides.** | Only when the user explicitly asks. Always prompt for confirmation. |

The IntentSelector toolchain follows this pattern (see [`IntentSelector_AI_Context.md`](../RoomRevive_unity/Assets/RoomRevive/UI/IntentSelector/Docs/IntentSelector_AI_Context.md)). Apply the same pattern to any new system.

---

## How to read a snapshot

A snapshot is a markdown file generated by an editor menu. It describes:

- The prefab hierarchy (object names, parent/child relationships)
- The components on each object
- Key serialized values that matter for behavior (font sizes, sprite paths, colors, references)
- Detected overrides — values that differ from what `CreateAll()` would produce

When you see a `### Override` callout in a snapshot, **do not regenerate that part**. The user changed it on purpose.

---

## Editing prefab / scene YAML directly

Last resort. Rules from the project README still apply:

- Don't reorder components.
- Don't rewrite `fileID` values.
- Don't touch a field unless you know its expected value.
- Validate by opening the file in Unity afterwards.

For everything else (typography, sprite swaps, layout tweaks): edit through the prefab in Prefab Mode, then export a snapshot so the next session sees your work.

## Concrete checklist (paste into a new conversation)

```
Before you change anything in this repo:

1. Read docs/AI_EDIT_PROTOCOL.md.
2. If touching the IntentSelector:
   - Read Assets/RoomRevive/UI/IntentSelector/Snapshots/IntentSelectorUI.md
   - Read Assets/RoomRevive/UI/IntentSelector/Docs/IntentSelector_AI_Context.md
3. Tell me what you found before proposing edits.
4. Default to Sync, never to Rebuild, unless I explicitly say "regenerate from scratch".
```
